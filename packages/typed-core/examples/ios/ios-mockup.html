🧩 Was sich konkret ändert

❌ Desktop-exklusiv

  • • Netflix/YouTube/Prime im Webview
  • • Widevine-DRM (Castlabs-Electron)
  • • Spotify in eingebettetem Webview
  • • Alles in einem Fenster
  • • Eigenes PiP-Fenster (pip.html)

✅ iOS-native Features

  • • Streaming-Dienste öffnen native App
  • • TV-Sender via AVPlayer (HLS, Hardware-dekodiert)
  • • Natives PiP (AVPictureInPictureController)
  • • Hintergrundwiedergabe (Control Center)
  • • AirPlay, Siri Shortcuts, Widgets

🔄 Workflow-Vergleich

💻 Desktop
📱 Netflix-Icon klicken → 🖥️ Netflix im Webview
📡 TV-Sender klicken → 🖥️ HLS.js in tv.html
🏠 Startseite → 🔄 Alle Dienste in einem Fenster
📱 iOS
📱 Netflix-Icon tippen → 🎬 Netflix-App wird geöffnet (↻ per URL-Scheme)
📡 TV-Sender tippen → 🎥 AVPlayer startet HLS-Stream (in der App)
🏠 Startseite → 📤 Weiterleitung zu Drittanbieter-Apps

📺 AppleTV – die Sonderrolle

Anders als iOS kann tvOS keine anderen Apps per URL-Scheme öffnen. Das macht AppleTV zum Spezialfall:

📡
TV-Sender (nativ)
AVPlayer + EPG + PiP = volle Funktionalität
Das Erste · ZDF · RTL · Sat.1 · ProSieben · arte …
🎬
Netflix
❌ kann App nicht öffnen
→
🌐
Webview (eingeschränkt)
⚠️ ohne Widevine – nur Free-TV
Lösungsansatz: AppleTV könnte Mediatheken (ARD, ZDF, arte) als native HLS-Streams abspielen (gleicher AVPlayer wie TV-Sender). Für Netflix/YouTube bleibt nur eine eingeschränkte Webview oder eine reine Fernbedienungs-Funktion (per AirPlay vom iPhone aus starten).

Alles in einer App.

Die volle Erfahrung wie gehabt.
Kernerkenntnis: Die iOS-App ist kein 1:1-Port. Sie ist eine andere App mit gemeinsamen Daten. Desktop bleibt der "Alles-in-Einem"-Player. iOS wird zum TV-Player + Streaming-Launcher + EPG-Browser. Der gemeinsame Nenner ist typed-core: Senderlisten, EPG, Verlauf, Konfiguration.
